No experiment is running. `data/site.json` has `experiment.enabled=false`; both variant maps are empty. Existing headline, hero and price copy are unchanged. Slots exist on home only: `headline`, `hero`, `price`. This is a presentation test, never authority to charge a different price.

To prepare a test after the owner chooses the offer:

1. Configure the existing Make It Do public PostHog project key and its regional ingest host. Use a public capture token, never a personal API token. Complete privacy/DPA/retention decisions in `LEGAL.md` and verify capture in that project.
2. In PostHog create a **multivariate, client-evaluable** flag with the same slug as `experiment.key` (default `launch-presentation-v1`), variants `control` and `variant`, equal rollout, web evaluation context. Keep it disabled while preparing. Link an experiment to this flag. Choose one primary metric and the minimum sample/run duration before launch.
3. Fill the variant map with only the changed slot. Example shape, with placeholders that must be replaced: `{"headline":"APPROVED TEXT"}`, `{"hero":{"src":"LICENSED-LOCAL-FILE.webp","alt":"ACCURATE DESCRIPTION"}}`, or `{"price":"APPROVED DISPLAY OF THE SAME CHECKOUT PRICE"}`. An omitted slot keeps the original. Do not change three things simultaneously if the aim is to identify which change worked. Control normally stays `{}`. Keep headline height and hero aspect ratio close to the control; rerun speed/CLS checks with the proposed values.
4. Run `python3 scripts/build.py`, serve on port 8115, then `tests/ab_smoke`. Also validate the actual configured assets and both chosen layouts at phone/desktop widths. The smoke fixture supplies test copy; it cannot approve your final variants.
5. Only after review set `experiment.enabled=true`, rebuild and deploy through the owner's publication process; enable the matching flag in PostHog. Neither action happened in this PR. To stop, disable the flag and then set the local config false and rebuild.

The head bootstrap calls the documented [PostHog flags API](https://posthog.com/docs/api/flags) using the consented visit ID. Only a returning, consented visit with an unexpired session is eligible. New visitors see the original; after consent their later home visit may join the test. This avoids hiding content while asking for permission. DNT, GPC, declined/missing consent, missing storage or missing configuration cause no flag requests. Assignment is per tab visit, not a cross-device person.

Only the three slots are held, with a 250ms deadline. Original content remains available without JavaScript. Timeout, network failure, unknown variants and responses after the deadline leave the original visible and emit no exposure. There is no late variant swap. The smoke test checks both variants, visibility and a hold below 300ms. A stalled browser can delay any JavaScript timer; this is a lab deadline, not a universal real-device timing guarantee.

`$feature_flag_called` has `$feature_flag`, `$feature_flag_response`, and the response request ID; `experiment_exposed` records the applied key/variant once per rendering. Both attach `$feature/<key>` to later CTA/checkout events. A consented checkout carries `mid_experiment` and `mid_variant`; the authenticated Gumroad importer copies them onto `order_paid`/`signup_completed`, with deterministic sale UUIDs. Do not count the thank-you URL or a button click as a sale. A checkout click proves intent, not that the off-site checkout loaded.

Compare to Gumroad totals for reconciliation; non-consented sales stay in Gumroad and are deliberately absent from PostHog. Check refunds, currency, assignment balance and the holdout/fallback rate. Set a free usage cap in the project before enabling. The first 100 visitors may yield too few consented exposures or sales to choose a winner; do not call a noisy difference a win.
